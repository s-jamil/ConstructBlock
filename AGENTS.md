# constructBlock project instructions

## Mandatory implementation documentation

The project owner requires every project change to be logged and explained in:
`documentation/constructBlock_Implementation_Progress_Report.docx`

- Read the current report before making changes. Preserve existing content and previous change log entries.
- For every task that changes this project, update the report in the same task before reporting completion. Cover code, contracts, frontend, backend, configuration, dependencies, architecture, diagrams, and documentation changes.
- Append a dated change log entry with a unique sequential entry number. Related changes may share an entry, but explain every change.
- Record what changed, affected files/components, why it was needed, resulting behavior, checks actually performed and their results, setup or migration steps, limitations, and follow-up work.
- Update the relevant implementation sections when behavior or architecture changes; the change log supplements the report rather than replacing its explanations.
- Clearly distinguish implemented and planned features, automated verification and manual checks, and completed and pending work. Never claim tests passed unless they were run or explicitly cite a dated earlier result.
- Do not include private keys, credentials, or confidential bid contents.
- Use the documents skill when editing the DOCX and render and inspect the updated pages. Never regenerate the report from an old temporary builder that would discard newer content or entries.
- If a report update cannot be completed, explicitly report the documentation gap; do not silently omit it or claim the task fully complete.
